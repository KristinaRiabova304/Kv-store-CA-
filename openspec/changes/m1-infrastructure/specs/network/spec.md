# Специфікація мережі

Тут я записую, якою має бути мережа. Кожна вимога має сценарій перевірки:
коли зробила ось це, тоді має бути ось так. Ключові слова Requirement, SHALL, WHEN, THEN
лишаю англійською, бо це формат OpenSpec.

## ADDED Requirements

### Requirement: Своя окрема мережа VPC
Система SHALL працювати у власній мережі з адресами `10.20.0.0/16`.
Ця мережа не має нічого спільного з default VPC sandbox і з мережами, які створюють лаби.

#### Scenario: після деплою мережа існує
- **WHEN** я задеплоїла стек `kv-network`
- **THEN** існує рівно один VPC з тегом `project=kvstore` і адресами `10.20.0.0/16`
- **AND** у ньому увімкнено DNS, тож сервери отримують імена, а не лише IP

### Requirement: Дві зони доступності
Підмережі SHALL бути у двох різних зонах AZ. Зона - це окремий дата-центр.
Це дає базу для реплікації в M3, але саме по собі не гарантує роботу при втраті зони:
при N=3 у двох зонах одна зона тримає дві репліки, і її втрата ламає кворум W=2, R=2.
Адреси для третьої зони зарезервовано в ADR-0003, рішення про неї я прийму в M3.

#### Scenario: підмережі в різних зонах
- **WHEN** я дивлюся список підмереж VPC
- **THEN** public-a і private-a знаходяться в зоні №1
- **AND** public-b і private-b знаходяться в зоні №2

### Requirement: Публічні підмережі мають інтернет
Публічні підмережі SHALL мати маршрут `0.0.0.0/0`, тобто все інше, на Internet Gateway,
і сервери в них SHALL автоматично отримувати публічну IP-адресу.

#### Scenario: маршрут у публічній підмережі
- **WHEN** я відкриваю таблицю маршрутів публічної підмережі
- **THEN** у ній є `10.20.0.0/16 → local` для зв'язку всередині мережі і `0.0.0.0/0 → igw-…` для виходу в інтернет

### Requirement: Приватні підмережі тільки для своїх
Приватні підмережі SHALL NOT мати жодного маршруту в інтернет,
і сервери в них SHALL NOT отримувати публічні IP.

#### Scenario: маршрут у приватній підмережі
- **WHEN** я відкриваю таблицю маршрутів приватної підмережі
- **THEN** у ній є лише `10.20.0.0/16 → local`

### Requirement: Security groups пропускають лише потрібний трафік
У мережі SHALL бути три security groups, по одній на кожну ланку системи:
- `kvstore-edge-sg` для балансувальника: пропускає HTTP на порт 80 з інтернету;
- `kvstore-coordinator-sg` для coordinator: пропускає трафік на порт coordinator лише від `kvstore-edge-sg`;
- `kvstore-shard-sg` для шардів: пропускає трафік на порт шарда лише від `kvstore-coordinator-sg`.

Жодна security group SHALL NOT відкривати SSH, порт 22.

#### Scenario: шард недоступний з інтернету
- **WHEN** я дивлюся вхідні правила `kvstore-shard-sg`
- **THEN** там є лише одне правило: порт шарда, джерело `kvstore-coordinator-sg`
- **AND** немає жодного правила з джерелом `0.0.0.0/0`

#### Scenario: coordinator доступний лише через балансувальник
- **WHEN** я дивлюся вхідні правила `kvstore-coordinator-sg`
- **THEN** там є лише одне правило: порт coordinator, джерело `kvstore-edge-sg`

#### Scenario: SSH закритий
- **WHEN** я перевіряю всі три security groups
- **THEN** у жодній немає правила для порту 22

### Requirement: Мережу можна відтворити з коду
Усю мережу SHALL можна створити й видалити тільки з файлу `infra/network.yaml`,
без жодних кліків у консолі.

#### Scenario: видалила й створила знову
- **WHEN** я видалила стек, а потім задеплоїла його ще раз
- **THEN** скрипт перевірки проходить, і я нічого не робила руками
